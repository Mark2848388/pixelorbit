PIXEL ORBIT INFINITE v5.0 — FULL DEVELOPER EDITION

ЧТО НОВОГО
- Полная панель разработчика в Профиле: RESOURCES, ITEMS, PLAYERS, EVENTS, WORLD CONTROL, AUDIT LOG.
- Разработчик назначается отдельной серверной таблицей pixel_developers. Клиентские метаданные не дают админских прав. Все изменяющие операции выполняются защищёнными Supabase RPC с серверной проверкой роли.
- RESOURCES: выдача кредитов и деталей в cloud_saves. Целевой игрок должен хотя бы раз сохранить игру в облако; иначе сервер вернёт target_has_no_cloud_save. После выдачи игроку нужно нажать «Загрузить из облака».
- ITEMS: каталог с кодом, названием, описанием и редкостью (common/uncommon/rare/epic/legendary/mythic), выдача количества в серверный инвентарь, отображение предметов в профиле.
- PLAYERS: список пилотов, отметка ограничения online-доступа и снятие ограничения. Клиент проверяет флаг при входе; это не удаляет аккаунт и не является блокировкой Supabase Auth на уровне провайдера.
- EVENTS: создание событий с расписанием и наградами; активные и будущие события видны игрокам в профиле. Автоматическая выдача наград/квестовая прогрессия пока не реализована.
- WORLD CONTROL: включение/отключение 10 секторов, множители кредитов и сложности врагов, сообщение сектора. Настройки загружаются из Supabase; отключённый текущий сектор переводит пилота в Орион.
- Журнал действий разработчика и сводные счётчики.
- Сохранён ключ локального прогресса pixelorbit_v4; добавлена новая версия Service Worker cache pixel-orbit-v50.

АКТИВАЦИЯ OWNER (ОДИН РАЗ)
1. Опубликуй содержимое папки PixelOrbit на GitHub Pages вместо старой версии.
2. Открой сайт, войди в свой обычный Pixel Orbit Online аккаунт.
3. Открой Профиль → DEVELOPER CONTROL. Если доступ ещё не активирован, панель покажет твой Auth UID и готовую SQL-команду.
4. В Supabase Dashboard → SQL Editor вставь показанную команду вида:
   insert into public.pixel_developers(user_id, role, active) values ('ТВОЙ_UID','owner',true) on conflict(user_id) do update set role='owner', active=true;
5. Выполни её как владелец проекта, затем вернись в игру и нажми «Обновить панель». Появится FULL ACCESS.

ВАЖНО
- Миграции v5.0 уже применены к подключённому Supabase-проекту, который использует исходный online.js. Файл SUPABASE_SETUP_v5.0_DEVELOPER.sql — воспроизводимая копия SQL для другого/нового проекта. Не запускай его повторно без необходимости; объекты создаются идемпотентно, но это всё равно DDL.
- Не вставляй service_role key в HTML/JS и не отправляй его в чат.
- Не выдавай себе права через пользовательские metadata. Единственный способ активации владельца — SQL Editor с правами владельца проекта.
- Выдача ресурсов работает с cloud_saves: у пилота должна быть облачная копия. Не нажимай «Загрузить из облака», если в облаке нет актуального сохранения.
- Созданные предметы хранятся в серверном инвентаре и показываются в профиле; боевые эффекты/экипировка предметов — следующий этап.
- События пока публикуются и отображаются, но автоматическое начисление их наград не включено.
